## 当前事实与目标

`codes/` 现有健康检查 API、PostgreSQL 开发容器、独立出站策略与传输模块，以及已在隔离数据库验收的内部连接表和凭据封装；尚无模型代理服务或凭据管理接口。已确认的产品目标是由管理平面持久化 OpenAI 兼容模型连接，以批准的 HTTPS origin 为目标，数据库只存加密的真实凭据，任务容器不接触凭据。首轮仅在本机单人、合成资料环境验证；生产部署与多人密钥治理尚未确定。

本设计收窄为**连接配置和凭据的持久化边界**。管理页面、任务令牌、运行中连接切换、真实供应商兼容和完整代理 HTTP 服务分后续任务。已完成的内部任务证明连接元数据与密文跨数据库连接重建可读，错误密钥或篡改密文不能得到明文，元数据查询不回显密钥；未接入真实凭据或现有试用容器。

## 建议边界

| 组件 | 首个持久化增量的职责 | 限制 |
| --- | --- | --- |
| 控制平面 API | 后续接收管理输入并展示非敏感连接元数据 | 不存明文，不读取解密主密钥，不向浏览器回显密文或明文 |
| 模型代理 | 唯一持有主密钥的应用组件；校验连接目标，封装加解密与持久化操作 | 不接受任务请求提供的 URL、连接 ID 或真实认证头 |
| PostgreSQL | 保存规范化 origin、base URL、模型 ID、连接状态与密文封装 | 不保存主密钥或可直接使用的明文凭据 |

候选数据记录包含：稳定连接 ID、显示名称、规范化 origin、经策略校验的 base URL、模型 ID、启用状态、凭据密文、随机 nonce、认证标签、密钥版本、创建与更新时间。凭据读取边界必须拒绝禁用记录。批准 origin 清单应有独立的持久记录；连接写入时精确匹配清单，出站前仍重新执行 DNS 与 IP 策略。仅凭数据库中的历史“已批准”标记不能绕过新连接检查。

内部封装采用 Node 标准加密 API 的 AES-256-GCM：每次加密独立随机 nonce，认证关联数据绑定连接 ID、规范化 origin、base URL、模型 ID 与封装版本；认证失败只报告稳定的内部故障类别。跨 origin 修改连接时必须重新提供凭据并生成新密文。后续模型代理应在请求经过任务授权和目标策略后才解密，明文仅在当前请求内用于构造上游认证头；不进入事件、日志或查询结果。数据库迁移在隔离测试库重复执行并保留版本记录；现有开发数据库未迁移。

已确认本地文件方案：在仓库之外的 WSL 用户专用位置保存独立的 32 字节随机主密钥，经只读挂载只交给模型代理；不得复用 `codes/.local/` 内的数据库密码文件。启动时缺失或长度错误就拒绝启动，不自动重新生成覆盖旧密文。密钥文件不得挂载到 API、数据库或任务容器。密钥更换需要单独的可回滚迁移任务；首个增量不暗中轮换。

## 验证、顺序与未决事项

1. [TASK-20260927-005](../planning/2026-09-27-006-model-connection-store.md) 已在临时 PostgreSQL 容器中用合成凭据验证创建、重读、重新连接、篡改拒绝、错误密钥拒绝和禁用连接，不修改现有开发数据库。该任务实现内部存储函数、版本化迁移及严格的密钥文件读取，不生成实际主密钥文件或公开管理接口；见验收。
2. 持久化验收后，再设计控制平面到模型代理的管理写入契约、管理员 origin 清单操作、运行中连接更新规则以及任务令牌与任务状态的事务边界。对外管理接口需机器可读契约和访问控制设计后才 Ready。
3. 最后将授权、持久配置、出站策略和 HTTPS 传输组合为产品代理，并用 Pi 容器和获准的测试上游回归。真实供应商需单独配置及兼容验证。

MPX-003 已决定本地丢失恢复边界。此处的密码封装与表字段是内部实现方案，不是已确认的产品管理契约。运行中连接切换、管理员身份与凭据轮换另在相应任务设计，不由本设计默认决定。
