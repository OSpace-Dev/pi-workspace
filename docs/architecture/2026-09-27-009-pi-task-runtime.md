## 范围和边界

本增量允许管理员在本机页面选择已启用模型连接，创建一个 Pi 0.87.1 任务，连续提问，明确结束后停止容器，恢复原会话，并在确认影响后删除容器及任务数据。任务运行不接收上传资料；多资料引用校验属于 Backlog 4。浏览器只接触任务 ID、状态、提问和回答，不接触任务令牌、供应商凭据、Docker API 或任意 Pi RPC 命令。

控制 API 负责状态、问答记录与编排；模型代理负责连接、授权和活动流；运行代理是唯一挂载 Docker socket 的服务，负责固定模板的容器和专用文件；任务容器内固定工作进程只接收 `prompt`，只等待 `agent_settled`。API、模型代理、运行代理和任务容器使用分离的网络和服务入口。任务容器不挂载 Docker socket、主密钥或管理员密钥。首轮只允许本机单人合成内容，不声称支持多租户或不可信代码执行。

## 数据和状态

`workspace_tasks` 以模型代理返回的 UUID 为主键，保存连接 ID、运行状态、当前授权 ID 和续期时间、错误类别、创建/更新时间。`workspace_turns` 保存任务内有序的用户文本、最终回答、结果状态与时间；不持久化完整 Pi RPC 事件或敏感上游响应。数据库迁移前滚，现有表不改写。运行代理以同一 UUID 派生容器名、数据目录和固定标签；删除时同时核对名称、标签和任务 ID，不通过前缀批量删除。

合法状态为 `starting`、`idle`、`answering`、`stopping`、`stopped`、`resuming`、`failed`、`deleting`。创建先取得代理授权，再写 `starting`，再准备并启动容器；失败时撤销授权，保留 `failed` 记录供诊断/删除。提问只从 `idle` 进入 `answering`，结束后回 `idle`；失败保留错误类别。结束先阻止新的提问，再撤销代理授权和活动流，最后停容器，成功才标记 `stopped`。恢复从 `stopped` 进入 `resuming`，签发全新令牌并原子更新文件，启动同一容器，成功后 `idle`。删除先撤销授权，运行代理仅删除匹配任务的容器和目录，成功后删任务与问答行；部分失败保留 `deleting` 供重试。

API、代理、Docker 和文件系统不共享事务。每个跨边界步骤可重复调用；启动时与周期性对账以代理状态和 Docker 状态修复 `starting/stopping/resuming/deleting`。不可判定时保留 `failed`，不宣称已停止或删除。恢复只接受保留容器和会话文件；缺失时显示故障，绝不静默创建新会话。单实例 API 调度器负责轮换；多实例部署需重新设计锁和活动流取消。

## 令牌与容器

代理创建返回 256 位随机令牌原值；API 仅在内存中短暂转给运行代理。运行代理将令牌写入任务专属目录的临时文件，`fsync` 后原子改名；整个目录以只读 bind mount 交给任务容器，避免单文件 bind mount 固定 inode。Pi `models.json` 的固定 `!cat` 命令在每次模型请求读取该文件，`auth.json` 不配置。写失败须撤销新授权。轮换在数据库 `renewAt` 到达时执行：代理写新摘要，运行代理换文件，代理确认并撤销旧摘要；失败则撤销新摘要。轮换后的旧令牌最多交叠五分钟，任务停止/删除时立即失效。API 重启时不持有原值；从文件读回当前原值只允许运行代理在内部核对/恢复流程使用，绝不返回浏览器。

容器基于已核实的 `pi-web-trial:pi-0.87.1` 构建专用工作镜像；不复用 Pi Web 试用容器。容器以非 root UID 运行，禁用提权和 Linux capabilities，限定 CPU、内存、PID，根文件系统只读，临时写入限于 tmpfs 和独立任务目录。Pi 使用显式 session 文件，以及 `--no-tools --no-extensions --no-skills --no-context-files`；工作进程不接受 `bash` 或配置类 RPC 命令。固定模型配置只指向代理，任务使用内部 bridge；同网服务仍可达并各自鉴权，该网络不构成强租户隔离。

首次创建空 session 文件，由 Pi 0.87.1 按其受支持的空文件逻辑初始化 session header；工作进程须收到固定 `get_state` 成功响应后才报告 ready，因此首次提问前结束/恢复也有可验证会话。运行代理另外区分 Docker running 与 Pi ready。运行代理保留 `CHOWN`、`DAC_OVERRIDE`、`FOWNER` 以管理专属 UID 的文件与读取私有服务密钥；任务容器仍 `cap_drop: ALL`。这不改变运行代理持 socket 的高权限事实。

配置的本地保护限额是每任务 512 MiB 内存、1 CPU、128 PID 和 64 MiB 临时目录，提问最大 32 KiB，单任务一轮回答同时执行，工作进程 120 秒期限。根目录只读意味着当前并不开放依赖安装；本轮验证保存工作目录与 Pi 会话，未来代码/依赖任务须重新设计可写层与镜像边界。

本地运行代理需要 Docker socket 和仓库外私有任务目录。它有宿主级潜在权限，必须只暴露带服务鉴权的固定任务操作，校验 UUID、容器标签、镜像与挂载目标，不提供 Docker 参数透传。预览使用独立 Compose 项目、数据库卷、任务目录和 `30203` 回环端口；现有 `30200`～`30202` 和 Pi Web 容器不迁移、不重建。

## 验证

在隔离 WSL Docker 项目和合成 TLS 上游验证：创建、同一进程两轮提问、停止后旧令牌失效、恢复同一 session、继续提问、自动轮换后的只读文件可见性、失败补偿、删除仅命中所属资源和任务间文件隔离。页面核对桌面与窄屏状态。真实供应商连接需单独在管理页面配置后验证兼容性；合成结果不证明供应商方言或一般问答正确率。
