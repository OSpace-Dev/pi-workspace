## 驱动因素与现状

第一轮仅在 Windows 本机回环地址演示，输入为合成 TXT/Markdown，单次最多 10 个文件、总原文 300 KiB。用户需要上传、提问、查看过程与引用原文、结束、恢复及在管理平面删除任务。Pi 不得执行代码或安装依赖。控制平面在 WSL Docker 中开发，不在 WSL 全局安装其运行时。

现有 `codes/` 尚无产品实现。现有 Pi Web 试用容器只是单人体验，不能承载管理平面或多任务隔离。Pi [RPC 文档](../../refer/pi-main-0.87.1/packages/coding-agent/docs/rpc.md)提供 JSONL 命令和事件；[CLI 文档](../../refer/pi-main-0.87.1/packages/coding-agent/docs/cli.md)支持显式 `--session`、`--session-id` 与 `--session-dir`；[安全文档](../../refer/pi-main-0.87.1/packages/coding-agent/docs/security.md)确认工作目录不是权限边界。具体恢复行为、模型运行与引用可靠性尚未实测。

## 候选边界

| 边界 | 首轮职责 | 明确不能做的事 |
| --- | --- | --- |
| Web 管理界面 | 任务列表、上传、问答、过程、引用回看、结束/恢复/删除 | 直接调用 Docker Engine 或透传 Pi RPC |
| 控制平面 API | 验证输入、持久化任务与资料及模型连接元数据、编排操作、过滤事件、校验引用 | 将浏览器发来的命令当作 Pi RPC 命令 |
| 模型代理 | 接收任务容器的 OpenAI 兼容请求，校验任务令牌，使用数据库中加密的连接配置代发上游请求并流式返回 | 把真实上游密钥返回任务容器或写进事件日志 |
| 运行代理 | 只接受控制平面的限定任务操作；创建、启动、停止、删除标记为本系统所有的容器及数据 | 暴露通用 Docker API 给浏览器或任意后台组件 |
| 单任务 Pi 容器 | 只处理该任务的资料和对话；保留工作目录、会话与容器可写层 | 挂载其他任务资料、宿主 Pi 凭据或 Docker socket |
| 持久化数据库 | 任务状态、上传资料与来源索引、事件与结果、容器身份、模型连接配置及加密凭据 | 将凭据密文与解密主密钥存于同一数据边界；用容器存在性替代任务记录 |

模型代理、数据库和本地服务拆分已由[本地拓扑决策](../decisions/2026-09-27-001-local-control-plane-topology.md)确认：TypeScript/Node API、独立模型代理、独立运行代理与 PostgreSQL。运行代理持有 Docker socket，仍可能拥有宿主级权限；缩小其 API 能减小误调用面，不能把它本身描述为低权限沙箱。Web 框架及详细契约尚待设计。

## 一条任务的建议流程

1. API 接收上传并校验格式、UTF-8、文件数量与字节上限，保存原文及稳定来源标识。引用索引将标识映射到文件、章节或段落；文件名仅用于展示，不作为信任依据。
2. API 请求运行代理创建该任务专用容器。容器只见该任务的输入和工作存储，设置资源限制。Pi 的 `models.json` 指向私有模型代理，使用任务级可撤销令牌，真实上游密钥不在容器中。Pi 以固定参数启动，禁用不需要的工具、扩展、Skill、上下文发现；宿主只发送允许的 RPC 命令。
3. 用户提问后，控制平面把可追溯的资料内容或检索片段交给 Pi。运行事件转换为受控的任务事件供 Web 查看。`prompt` 接受不等于回答完成；以 `agent_settled` 和错误事件判定本轮回答状态。
4. 一轮回答完成，任务转为“待继续”，容器仍运行。用户明确结束任务后，控制平面停止容器并标记“已停止”。结束与停止失败须分别记录，不能在停止未成功时显示已停止。
5. 用户恢复时，启动同一个已停止容器，重新连接 Pi RPC 并使用明确的会话身份恢复；文件状态、Pi 会话与新进程的恢复均需实测。若容器或会话缺失，展示恢复失败并保留可诊断记录。
6. 用户在管理平面执行删除时，确认目标任务及资料、会话、结果、容器的影响范围。删除是不可恢复操作；后端按可重试步骤移除系统拥有的资源，部分失败显示未完成状态并允许重试。具体确认交互在界面设计中定义。

## 状态与故障边界

候选状态：`created`、`starting`、`running`、`answering`、`idle`、`stopping`、`stopped`、`resuming`、`failed`、`deleting`、`deleted`。状态名称及跨服务契约仍待设计。`idle` 只表示可继续提问，不触发自动停止；本地闲置容器的资源占用需要上限与提示。重复结束或恢复不能创建额外任务容器；任务记录以稳定内部 ID 关联唯一受管容器。启动、停止或删除过程中 API/代理重启时，须与 Docker 实际状态对账。

现有证据：2026-09-27 以同版本 Pi 镜像创建独立临时容器，第一次启动写入 `/tmp/piws-resume-marker` 并输出 `created`，停止后再次启动同一容器输出 `resumed`；测试容器随后删除。这只证明该容器可写层跨 stop/start 保留，不证明 Pi 会话、模型凭据或容器删除后的依赖恢复。

## 安全与资料边界

- Pi 的 `--no-tools` 仅限制模型工具；[RPC 实现](../../refer/pi-main-0.87.1/packages/coding-agent/src/modes/rpc/rpc-mode.ts)仍有宿主调用 `bash` 的路径。控制平面必须只发送其明确支持的操作，不能透传任意 RPC 命令。
- 上传文本可能包含提示注入。引用必须由 Workspace 校验来源标识和位置；模型生成的出处文本不能直接当作真实链接。内容是否支持断言需在首轮样例中人工核对。
- Docker Engine 权限集中在运行代理，并限制容器标签、名称、挂载与资源配置。仅能删除本系统创建且与任务记录匹配的资源。运行代理本身仍是高风险组件。
- [模型接入决策](../questions/2026-09-27-001-model-access.md)已选择控制域代理和数据库配置。供应商密钥从管理界面输入后加密入库；加密主密钥从数据库及仓库之外注入代理。代理用任务级令牌授权、限定模型连接、请求大小和并发；令牌撤销、上游重定向、私网地址与 DNS 变化需在详细设计中处理，避免配置任意上游地址造成内网访问。日志与事件只记录不含凭据的诊断。
- Pi 0.87.1 的[模型文档](../../refer/pi-main-0.87.1/packages/coding-agent/docs/models.md)允许将 `models.json` 的兼容端点指向代理；[openai-completions 实现](../../refer/pi-main-0.87.1/packages/ai/src/api/openai-completions.ts)使用 Chat Completions 的流式接口。首轮代理以此协议为验证起点，不能仅因上游宣称“兼容 OpenAI”就假定工具调用、错误格式和流式分块都一致。
- 首轮本地回环访问和合成资料不能证明多用户授权或真实资料安全；多人方案需另外设计身份、资料归属、保留、配额与审计。

## 实施前技术选择

| 待选项 | 候选及取舍 | 下一步 |
| --- | --- | --- |
| Pi 接入 | 容器内 RPC 易于进程隔离与事件桥接；SDK 方便自定义工具，但需要自有容器工作进程。倾向先验证 RPC。 | 实测有模型事件、显式会话恢复和取消，再决定正式适配器 |
| 控制平面语言 | TypeScript/Node 已确认；Web 框架未选。 | 先验证 API 的容器化开发入口 |
| 持久化 | PostgreSQL 容器已确认。 | 首个任务验证健康状态与连接，具体模式随功能设计 |
| Docker 接入 | 专用运行代理容器独占 Docker socket 已确认，仍具有宿主级潜在权限。 | 首个任务不挂载 socket；运行代理实施前定义固定操作和资源归属校验 |
| 凭据与网络 | 已确认模型代理持真实供应商密钥，数据库加密存储连接配置；Pi 容器使用代理令牌和私有网络。 | 实测 OpenAI 兼容流式调用、令牌隔离和凭据脱敏；决定主密钥注入与轮换机制 |

## 设计验证与准入

需要验证 Pi 0.87.1 将模型请求发至 OpenAI 兼容代理、流式响应、一次回答与 `agent_settled`、继续追问、显式会话恢复、异常退出、停止/删除；验证不同任务资料不能互读，日志与事件不含上游密钥。实际供应商可由管理平面后续配置，先用无真实密钥的兼容端点验证代理协议。状态机、产品 API 和界面流程在对应任务实施前设计；已确认拓扑允许先执行[容器化开发入口任务](../planning/2026-09-27-002-control-plane-dev.md)，其范围不包含这些未确认契约。
