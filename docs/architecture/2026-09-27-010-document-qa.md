## 数据与职责

控制 API 的 document-input 负责严格 UTF-8、扩展名、字节与批次校验；document-store 负责迁移 006、来源与事务；document-answer 负责提示与结构化答案验证；document-routes 提供管理契约。运行代理只传递固定 prompt，Pi 保持无工具模式。前端资料列表、答案渲染、原文页面各有模块。

原文件保存为 bytea，并保存无损解码文本、SHA-256、UUID、文件名、字节数及创建时间。来源只能追加，不能覆盖或单独删除；同名拒绝，整任务删除级联删除资料与回答。上传事务锁定任务行，只允许 idle/stopped，检查已有资料加本批次的 10 文件/100 KiB 单文件/300 KiB 总计上限，全批成功或全批失败。文件名不是文件系统路径。原始字节及 BOM 不改变；禁止 NUL，因 PostgreSQL text 无法保存。不支持 PDF、二进制或 HTML 渲染。

回答开始在同一事务锁定 idle 任务、冻结全部来源 UUID、写 pending turn、将任务改为 answering。以后追加文件不改变旧轮次出处。来源原文长期保留至任务删除；停止与恢复不删来源。

## 上下文与答案

采用完整资料文本上下文。相较关键词检索，完整上下文不会在本轮小规模样例中漏掉冲突资料；没有向量服务或额外模型调用。每轮资料 JSON 作为不可信数据，与控制提示分隔；不允许执行其指令。问题保持 32 KiB 限制，内部 prompt 上限 768 KiB，HTTP 上限 1 MiB；超预算报 DOCUMENT_CONTEXT_TOO_LARGE，不截断。300 KiB 上传不是任意模型上下文保证。Pi 历史继续累积；产品代理保留 1 MiB/64 消息限制，上游上下文拒绝以失败展示，后续上下文管理进入 Backlog，不在此轮引入隐式摘要或新计费调用。

输出为 JSON：status=answered/no_basis/conflict，claims=[{text,citations:[{sourceId,quote}]}]。事实回答每个 claim 必须有引文；no_basis 不得带引用。每个引文必须属于本轮 snapshot，quote 非空、最长 2000 字符，并在对应原文唯一匹配。服务端计算 start/end（JS UTF-16 偏移）、章节与段落定位；重复引文无法唯一定位时拒绝。语法错误、虚构 ID、不匹配或含糊引文均使本轮 failed，原始模型输出不向浏览器伪装成有效回答。原文页使用 textContent 与 mark，禁止 Markdown/HTML 执行。

引文匹配只证明位置与原文相同，不证明语义支持。样例验收分别核对事实与原文；任意模型正确率未认证。no_basis/conflict 是模型声明，结构约束不代替语义评判。

## 状态、安全、兼容

等待页面轮询数据库任务/轮次，展示准备资料、模型回答、出处校验、完成/失败阶段；不传递原始 RPC、思考内容或令牌。结束操作仍可中断回答。失败写错误码，不能成功展示。API 重启中断回答恢复沿用运行任务设计。

迁移 006 只加表/列，不修改迁移 005 校验和；旧无资料任务继续普通问答，添加资料后进入资料问答。新 worker 使用独立镜像标签，新预览使用独立 Compose project/端口/数据库与目录。旧容器不重建。回退停新项目，旧预览仍可用。

## 验证

UTF-8/BOM/空白/格式/字节边界、批次原子性、任务状态竞争、快照、引文虚构/歧义/不匹配、原文 XSS、停止恢复删除与重启持久化。真实 Pi + 合成 TLS 上游验证协议；固定响应不证明真实模型推理。真实供应商由用户配置后按同一合成样例复验。
