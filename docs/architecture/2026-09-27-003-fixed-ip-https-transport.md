## 现状与范围

`codes/src/model-proxy/upstream-policy.ts` 已返回规范化 base URL、原域名、选定的公网 IP 和地址族，但目前没有代码使用该结果发起连接。本增量只实现内部 HTTPS POST/SSE 传输，不启动产品代理、不处理任务令牌、真实供应商凭据或数据库配置。调用方必须先取得策略结果；传输层不接受由任务请求提供的目标地址。

## 连接与请求

1. 从策略结果的 `baseUrl` 拼接固定的 `chat/completions` 路径，保留其基础路径和规范化 origin。只发起 POST，路径、方法和目标不由下游请求覆盖。
2. 每次请求创建独立的 Node `https.Agent`，关闭 keep-alive 和 TLS session cache。Agent 的 `lookup` 只返回策略结果的 IP/地址族；连接建成后再次核对 socket 的远端 IP 和地址族，失配即销毁请求。`https.request` 的 hostname 始终为原域名，故 Host、SNI 与证书主机名验证仍使用原域名。保留 TLS 默认信任链和证书验证。响应结束、出错或取消时销毁该 Agent；新请求须重新执行目标策略。
3. 原生 `https.request` 不自动跟随重定向。传输层将所有 3xx 视为拒绝，不读取 `Location`，不转发响应体。拒绝非 2xx、非 `text/event-stream` 的响应；上游响应正文与头部不进入错误文本。
4. 请求体由上层已校验的 JSON 字节提供；传输层只设置必要的 JSON/SSE 请求头。真实认证头在后续产品代理边界注入。本增量不添加重试，也不使用环境 HTTP 代理。

## 流与故障

- 返回 Node 可读响应流，由消费方以背压方式转发；响应流错误和中止必须传播，下游断开时通过 `AbortSignal` 取消上游。消费方负责识别 SSE 正常结束标记；没有 `[DONE]` 的完整 EOF 不得视为成功。
- 连接/握手失败、请求超时、3xx、非 2xx、错误内容类型分别归为内部稳定错误类别；不得包含 URL、IP、证书详情、上游正文、令牌或密钥。响应头后出现的流错误由消费方处理，不能改写已发出的 HTTP 状态或伪造 `[DONE]`。
- 本地传输调用方明确提供首响应期限和流空闲期限；达到期限时销毁请求。具体产品限额由后续代理接口设计确定。取消不重试，避免重复计费或片段。

## 验证与剩余边界

在独立 WSL Docker 检查容器内启动本地 TLS 测试服务，使用临时测试 CA 和模拟策略结果覆盖：实际连接 IP、原域名 Host/SNI/证书校验、证书主机名不符、3xx 不跟随、分块 SSE、上游失败、取消与空闲超时。测试用回环地址仅用于传输夹具；产品目标策略仍拒绝回环和私网。测试不触达真实供应商或现有容器。后续产品代理仍需完成授权、凭据、正文校验、SSE 结束判定和 Pi 集成。
