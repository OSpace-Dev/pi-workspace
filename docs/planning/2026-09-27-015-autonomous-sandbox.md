## 交付范围

一个可操作增量交付：无需控制域模型连接创建沙箱；沙箱内 Pi Web 自主配置并直连合成上游；独立配置和会话的停止恢复；管理端容器/就绪探针；删除和资源收口。跨数据库、API、运行代理、Docker 网络及管理页，需要独立迁移和契约更新。旧 QA、代理连接和旧沙箱数据只做兼容，不扩大其产品功能。

## 验收与验证

按新需求 1～5；增加数据库迁移前后、旧沙箱只读/生命周期兼容、容器归属拒绝、两个沙箱网络与文件隔离、异常退出和探针未知状态测试。开发者级检查后只读复核、隔离 Docker 端到端及桌面/手机页面检查；验收项目结束必须移除临时容器/网络并更新台账，保留必要的卷和任务目录证据。

## 实施顺序

1. 建立独立沙箱存储与服务，明确新旧类型路由和补偿/对账；更新 API 契约。
2. 运行代理创建沙箱专属出站网络和 Pi 目录，移除新沙箱代理 token 配置；实现状态探针和生命周期。
3. 管理页去掉沙箱创建的连接选择，展示探针状态、时间及 Pi Web 入口；不把模型密钥送到控制平面。
4. 隔离验收与复核，替换唯一预览，清理验收环境，更新资源台账。

容量假设：Codex 在连续开发周期完成以上闭环；回环入口、单机 WSL Docker，SBX-005 已确认可信本地直接出站。生产公网、多用户另立任务。旧控制域模型代理仍服务历史 QA，不在本任务删除。
