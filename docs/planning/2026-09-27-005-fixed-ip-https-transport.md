## 目标与范围

实现一个内部流式 HTTPS 客户端，使用出站策略返回的固定 IP 建立连接，以原域名执行 TLS 验证，并拒绝重定向。交付可供后续产品代理消费的响应流与稳定错误类别。

- 包含：固定路径的 POST、单次连接 IP 固定、原域名 Host/SNI/证书验证、3xx 拒绝、SSE 响应流、取消、首响应与空闲超时、聚焦测试。
- 不包含：对外代理服务、任务授权、密钥、数据库清单、真实供应商接入、Pi 容器端到端验收、SSE 内容改写。
- 依赖：已验收的目标策略；Node 24 和现有 WSL Docker 可用。测试 CA 只在测试进程中使用，不成为运行配置。
- 可回退假设：首轮不复用连接或 TLS session；每个请求前由调用方重新执行目标策略。无已确认供应商要求连接复用。

## 完成定义与验证

1. 测试服务确认请求抵达策略指定的 IP，Host 与 SNI 为原域名，合法证书通过，错误主机名或不可信证书失败。
2. 3xx 不产生第二次请求；非 2xx 和非 SSE 响应不透传正文或敏感头；分块 SSE 按顺序可消费。
3. 取消、响应流中断和超时释放连接；无自动重试。类型检查、聚焦测试在新建的 WSL Docker 检查容器中通过，不影响现有容器。
4. 开发者验证、只读评审、验收及剩余风险记录完成。

## 迭代与回退

本轮只处理上述内聚传输任务，不启动或改动现有 API、数据库与 Pi Web 试用容器。实施失败时仅回退本任务新增的传输模块、测试和脚本；保留现有目标策略。后续再设计产品代理的正文限制、认证、凭据和 SSE 终止语义。
