## 目标与边界

在 WSL Docker 中，让独立临时 Pi 0.87.1 容器通过一个固定测试端点完成流式请求，捕获请求形状和 RPC 事件，并验证错误在 Pi 侧如何表现。测试端点和测试令牌只供本任务使用，不能作为已实现的产品模型代理或凭据方案。

- 包含：固定的无外网测试上游、最小令牌/模型检查、SSE 分块、上游拒绝与断流场景、可复现命令及脱敏结果。
- 不包含：真实供应商、数据库持久化、加密凭据、用户配置、任意上游 URL、长期运行的模型代理服务、Web 界面。
- 假设：沿用 Pi Web 试用时已取得的同版本镜像作为只读镜像来源，不读取或挂载试用容器的配置、卷和凭据；临时网络与容器在验证后清理。测试只使用合成输入和假令牌。

## 完成定义

1. 合法测试任务令牌触发 Pi 流式 `message_update`，最终得到 `message_end` 和 `agent_settled`；记录请求字段和 Pi 实际事件，不将 `prompt` 命令成功误判为回答完成。
2. 无效令牌、另一任务令牌及不匹配的模型均在测试上游生成回答前被拒绝。
3. 上游拒绝、含假敏感文本的错误正文及中途断流不会在返回给 Pi 的错误或测试日志中暴露假敏感文本；Pi 的最终状态必须被记录为失败，不得当作成功答案。
4. TypeScript/Node 代码若落入 `codes/`，完成类型检查或可执行测试；实验网络及容器可按文档移除，不影响当前 API/数据库和 `pi-web-trial`。
5. 根据实测更新[代理接口草案](../api/2026-09-27-001-model-proxy.md)、Backlog 和测试结果。真实上游与持久令牌的实施继续等待[MPX-001～002](../questions/2026-09-27-002-model-proxy-boundary.md)。

## 验证与回退

在临时 Docker 网络中启动测试端点与 Pi 容器，逐项运行上述场景并记录最少量脱敏事件。实验失败时保留诊断和任务未完成状态；实验结束仅移除本任务创建的临时资源。现有 Compose 服务和试用容器不属于清理范围。

## 结果

2026-09-27 在 WSL Docker 中完成固定测试上游的 Pi RPC 验证。正常、上游拒绝和断流三种场景分别得到 `stop`、`error`、`error`，均有 `agent_settled`，假敏感标记与假令牌未出现在事件或夹具日志。请求字段和拒绝结果见验收记录。[初评发现](../reviews/2026-09-27-002-model-protocol-probe.md)已修复并复审通过。临时容器和网络已清理。
