## 迭代目标与容量

在一个独立 WSL Docker 预览中，从管理页面完成任务创建、连续提问、结束、恢复和删除；任务使用正式只读令牌目录、自动轮换与代理授权。Codex 执行实现与隔离验证，项目发起人评审可操作页面。此轮不交付资料上传、出处校验、多人权限或生产部署。

## 完成定义

1. 任务页面有可直接访问的列表和详情路由，浏览器不收到任何任务或供应商凭据。
2. 一个任务的两轮提问使用同一 Pi 会话；用户结束后容器停止，恢复后继续原会话和工作目录；删除后容器及目录不可恢复，失败可重试。
3. 授权令牌位于任务只读挂载目录，轮换与撤销满足已确认时间窗口；任务之间无法读取彼此目录，删除不能触及非本系统资源。
4. WSL Docker 的独立项目使用合成 TLS 上游通过正常和故障路径验收；现有容器、端口和卷保持原状。
5. 类型检查、相关测试、自我复核、只读评审及验收记录完成；Backlog 和导航同步。

先实现代理恢复/轮换接口与运行代理，再接 API 状态和工作进程，最后接页面与隔离验收。技术假设：单实例本地控制 API、固定资源上限与单任务同时只执行一轮提问，均可在后续设计中调整。真实供应商配置不是本任务准入条件。

## 交付结果

- `codes/src/runtime-agent/` 独占 Docker socket；`codes/src/task-worker/` 提供固定 Pi RPC 桥；`codes/src/api/task-*` 提供事务状态、问答存储与限定编排。页面按任务列表、详情、会话和 API 模块组织，真实路由为 `/tasks` 与 `/tasks/:id`。
- 只读令牌目录、自动轮换、失败补偿与指纹对账已接入；每次恢复签发全新授权。结束与删除先撤销访问和活动流，再操作受管环境。
- [复审](../reviews/2026-09-27-011-pi-task-runtime.md)四项发现已修复；验收包含真实 Pi 合成 TLS 调用、空会话/连续追问/恢复、自动轮换、上游错误、回答中结束、删除、文件隔离、归属拒绝、102 条任务/状态竞态/失败补偿、桌面和移动操作。
