## 目标与范围

把已验收的目标策略、HTTPS 传输、凭据库和令牌摘要接成一条可由 Pi 0.87.1 消费的受控 SSE 调用链。包含代理任务创建/停止、产品流式入口、停止取消活动流、模块化管理服务与现有页面导航整理，以及隔离 WSL Docker 验证。控制 API 不把任务令牌交给浏览器。

正式 Pi 容器编排、只读令牌文件和自动续期不在本任务内；这三项完成前不宣称 Backlog 2B 完成或文档问答已可用。真实供应商调用只在管理员自行配置连接后另行兼容验证。

## 验收

1. 内部服务授权创建代理任务后，仅该任务当前令牌与绑定模型能流式调用；停用连接、停止任务、过期或撤销令牌拒绝新调用。
2. 停止任务会撤销令牌并中断正在进行的上游流；并发创建/停止不能留下活动授权。
3. 每次调用重跑批准 origin 与公网 DNS 策略；传输用策略 IP、原域名 TLS，禁止重定向；上游密钥只作为受控认证头发送，不可被 Pi 覆盖。
4. 非法字段、工具、非流式、超限和错误模型在出站前拒绝；上游错误与断流不回显正文/头部/密钥，也不伪造成正常完成。
5. 管理连接和 origin 仍可通过各自 URL 操作；既有容器、卷和试用 Pi 容器不变。

## 验证方式与容量

一个连续实施周期由 Codex 完成。先运行 TypeScript 检查和相关单元/集成测试，再用独立 WSL Docker 项目验证 PostgreSQL 迁移、状态、Pi SSE 和失败路径；复核变更与记录已知限制。仅使用合成凭据和隔离资源，不触碰 `piws-admin-preview` 数据卷。

## 交付与下一步

产品代理按应用装配、连接管理、任务控制、Pi 请求和流转发拆分；控制 API 按会话、转送、页面路由及入口拆分；管理前端按 API 客户端、会话、连接与 origin 视图拆分，真实路径为 `/models/connections` 与 `/models/origins`。新预览在独立 WSL Docker 项目使用回环 `30202`，管理密钥沿用原有仓库外文件。

见[评审与复审](../reviews/2026-09-27-010-product-model-proxy.md)和验收。下一轮以可操作任务闭环为目标，将运行代理、正式只读令牌文件、自动轮换及任务页面作为一个有序增量设计实施；不再把每个存储原语当作独立用户交付。
