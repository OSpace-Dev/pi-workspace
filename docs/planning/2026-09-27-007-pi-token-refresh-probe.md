## 目标与边界

验证 Pi 0.87.1 同一 RPC 进程中的第二次模型请求能通过固定 `!command` 配置读取任务文件中原子替换后的新代理令牌，从而给 MPX-006 的建议方案提供实测依据。

- 包含：临时合成令牌、固定无凭据测试端点、两轮 Pi RPC 提问、第一轮后旧令牌拒绝、新令牌接受、输出脱敏与临时资源清理。
- 不包含：真实供应商、数据库授权表、任务容器正式挂载、管理接口、令牌续期调度或现有 Compose/Pi Web 容器改动。
- 依赖：本地已有 `pi-web-trial:pi-0.87.1` 与 `node:24-bookworm-slim` 镜像；WSL Ubuntu Docker。只读使用 Pi 镜像，不挂载试用配置和卷。
- 可回退假设：测试中的文件和命令由控制域固定配置，只模拟专用文件原子替换；这不证明恶意任务无法编辑正式配置。

## 完成定义

1. 第一轮使用旧合成令牌，产生 Pi `message_end.stopReason: stop` 与 `agent_settled`。
2. 第一轮后端点拒绝旧令牌，任务文件原子替换为新值；同一 Pi 进程第二轮仍成功，端点只见新令牌的代数，不打印原值。
3. 测试失败时退出非零；摘要、RPC 事件和服务日志不含合成令牌；临时网络与容器自动清理。
4. 在 WSL Docker 中执行并记录版本、输出、限制及对后续设计的影响；不把技术探针标成产品令牌实现。

## 结果

2026-09-27：同一 Pi 0.87.1 RPC 进程先用旧令牌成功，控制域模拟原子替换文件后再用新令牌成功。端点在第一轮后已拒绝旧值。输出脱敏、临时资源清理与现有容器保持运行的证据见验收；[只读自评](../reviews/2026-09-27-006-pi-token-refresh-probe.md)通过。该结果解除 Pi 重读能力的技术疑点，但不使产品令牌实施 Ready。
