## 目标与范围

实现一个不发起网络请求的目标策略模块：给定模型连接 base URL、管理员批准的 origin 列表和一次 DNS 解析结果，返回后续 HTTPS 连接必须使用的规范化 URL、原主机名与已校验的 IP/地址族，或明确拒绝。此任务验证安全边界中最容易被 URL 解析和 DNS 地址变化绕过的部分。

- 包含：HTTPS URL 和批准 origin 的结构化校验、规范化后的精确匹配、公网地址分类、混合 DNS 结果拒绝、可注入 DNS 解析器及聚焦测试。
- 不包含：真实 HTTPS 请求、TLS、重定向处理、数据库清单、模型密钥、任务令牌、代理服务、Web 管理入口。后续连接适配器必须消费本模块返回的固定 IP，不能自行重新解析。
- 技术假设：本地首轮只接受域名目标，不接受 IP 字面量；base URL 不带用户信息、查询或片段。被拒绝时不在错误文本里回显目标。供应商确需例外时另行设计。

## 完成定义

1. 有效的获准 HTTPS 域名和纯公网 DNS 地址成功返回规范化目标与固定 IP；清单为精确 origin，前缀相似、子域伪装和未批准端口不匹配。
2. HTTP、带凭据/查询/片段的 URL、IP 字面量、空或错误 DNS 结果、私网/回环/链路本地/保留/多播/IPv4 映射私网地址以及公私混合结果均被拒绝。
3. 测试使用合成地址和可注入解析器，不请求真实供应商或现有试用环境；类型检查与聚焦测试在 Docker 内通过。`ipaddr.js` 2.5.0 作为 MIT 直接依赖记录在锁文件中。
4. 开发者级验证、只读评审及验收记录完成；不把该策略模块误称为已实现产品代理。
