## 1. 确认首个可验收的文档问答切片

- 目标：内部成员可以用代表性样例说明上传什么资料、提出什么问题、如何核验答案和出处。
- 范围：TXT、Markdown 的示例；无依据时的回答、资料保留期限、环境恢复方式和最小输入规模的决策；形成已确认的需求与验收条件。PDF 不进入首个增量。
- 可观察验收：需求记录给出至少一个正常问答和一个无依据或错误输入场景，明确输入、预期结果、引用定位与失败表现，并由产品决策人确认。
- 验证方式：用样例资料逐条走查需求和验收条件，核对相关问题记录均有结论。
- 状态：首轮需求已[归档](../requirements/2026-09-27-001-document-qa-local-slice.md)，含管理平面删除与用户结束后停止；本条完成。模型接入和技术架构作为后续设计依赖。

## 2. 让控制平面在 WSL Docker 中开发和调试

- 目标：开发者只需 WSL 的 Docker 与 Compose，就能启动、调试和停止控制平面服务，不在 WSL 主机全局安装应用运行时或数据库。
- 范围：选定技术栈后的容器化开发入口、源码挂载、日志、热重载与开发数据卷；控制平面与任务沙箱分离。具体容器职责和 Engine 访问方式待设计。
- 可观察验收：按仓库记录的命令可启动最小控制平面服务并观察健康状态；修改 `codes/` 内代码后开发容器能反映变化；停止服务后 WSL 主机没有新增后台应用进程或全局依赖。
- 验证方式：在现有 WSL Docker 环境按记录的步骤执行启动、修改、观察、停止，并检查容器、卷与宿主进程状态。
- 状态：本地拓扑已[确认](../decisions/2026-09-27-001-local-control-plane-topology.md)；[首个容器化开发入口任务](2026-09-27-002-control-plane-dev.md)已完成并通过验收。业务管理能力仍待后续增量。

## 2A. 验证模型代理的最小协议边界

- 目标：证明独立模型代理能接收 Pi 0.87.1 的 OpenAI Chat Completions 流式请求，在任务容器不持真实上游凭据时返回事件。
- 范围：先使用无真实密钥的兼容端点或受控测试上游，验证代理令牌、流式响应、错误、日志脱敏和任务级访问；真实供应商配置与加密存储随后实现。
- 可观察验收：合法任务令牌可完成一次受控流式回答；无效或跨任务令牌被拒绝；代理和 Pi 事件不泄露真实上游密钥，代理不可访问非允许上游目标。
- 验证方式：协议集成测试和 WSL Docker 中的临时 Pi 任务容器验证，记录请求、事件与错误状态，不使用现有 Pi Web 试用凭据。
- 状态：[模型代理设计](../architecture/2026-09-27-002-model-proxy.md)与[接口草案](../api/2026-09-27-001-model-proxy.md)已形成；无凭据、固定测试上游的[协议验证任务](2026-09-27-003-model-protocol-probe.md)已完成并验收。真实上游目标和令牌边界已由[决策](../decisions/2026-09-27-002-model-proxy-boundary.md)确认。

## 2B. 落实模型代理的真实上游与授权边界

- 目标：在受控配置下，模型代理只连接管理员批准的公网 HTTPS 目标，并凭任务专属、可撤销的授权转发 Pi 请求。
- 范围：先做[出站目标策略](2026-09-27-004-upstream-target-policy.md)，再做固定 IP 的 HTTPS 流式传输、模型连接与密钥持久化、任务令牌及生命周期集成；管理入口随对应接口设计实施。
- 可观察验收：未批准或非公网目标在连接前拒绝；实际连接 IP 与校验结果一致且 TLS 校验原域名；任务停止/删除/切换连接后旧令牌不可调用，恢复令牌仅能访问新绑定连接；真实上游密钥不进入任务容器和日志。
- 验证方式：DNS/地址策略测试、受控 HTTPS 连接和重定向测试、数据库与令牌集成测试、Pi 容器流式与错误回归。真实供应商需用管理平面配置后单独做兼容验证。
- 状态：[出站策略](2026-09-27-004-upstream-target-policy.md)、[HTTPS 传输](2026-09-27-005-fixed-ip-https-transport.md)、[加密持久化](2026-09-27-006-model-connection-store.md)、[授权存储](2026-09-27-008-task-token-store.md)、[时间窗口](2026-09-27-009-task-token-window.md)、[管理工作台](2026-09-27-010-model-management-console.md)、[产品流式代理](2026-09-27-011-product-model-proxy.md)及[运行闭环](2026-09-27-012-pi-task-runtime.md)已验收。只读文件、自动续期、停止撤销、活动流取消、同会话恢复及删除已集成；任务更换连接仍待独立设计，本条整体未完成。

## 3. 验证独立沙箱内 Pi 的运行与收口

- 目标：证明 Workspace 可以启动、观察、停止并清理一个独立的 Pi 任务环境。
- 范围：基于 Pi 0.87.1 的单任务技术验证；任务事件、资源限制、文件边界、进程退出、保留与恢复。不包含正式多用户平台。
- 可观察验收：一个任务启动后能观察到 Pi 事件；任务结束后容器停止，再启动时原工作目录和依赖状态可用；另一个任务无法读取前一个任务的私有文件。
- 验证方式：本地自动化或可重复命令验证启动、事件、取消、恢复及任务间隔离，并记录限制。
- 状态：已完成[可操作任务闭环](2026-09-27-012-pi-task-runtime.md)并通过隔离验收。页面可创建、提问、结束、恢复和删除，真实 Pi 会话、同一容器/工作目录保留、任务文件隔离、只读授权及异常退出均有证据。当前禁止依赖安装，依赖恢复能力不从此结果推定。

## 4. 交付多资料问答的第一条 Web 闭环

- 目标：内部成员在 Web 中上传资料、发问、查看实时过程，收到带可回看原文出处的回答。
- 范围：TXT/Markdown 的受控上传、文本定位、Pi 问答、引用校验、任务阶段、资料栏与独立原文路由；Agent 不执行代码或安装依赖。
- 可观察验收：用户上传多份 TXT/Markdown 资料后能收到答案；每个引用能打开对应文件的章节或段落；无可用依据及解析失败有明确结果。
- 验证方式：使用条目 1 确认的样例端到端测试，核对引用位置、失败状态和任务记录。
- 状态：[TASK-20260927-012](2026-09-27-013-document-qa.md)实现与受控验收完成，产品 30205、合成演示 30206。资料、回答、出处、原文、停止恢复删除均可操作；真实供应商语义未执行，不能宣称最终业务验收通过。

## 4A. 管理端启动独立 Pi Web 沙箱

- 目标：管理员在页面启动命名沙箱，每个沙箱有独立 Pi Web、工作文件、会话、访问密码与模型授权。
- 范围：本地回环入口、独立容器和目录、受限工具调用、停止/恢复/删除；不含多人身份、生产远程访问或强隔离承诺。
- 可观察验收：创建两个沙箱能分别登录和调用模型；文件及密码不同；停止撤销授权，恢复保留会话，删除清理容器与目录。
- 验证方式：WSL Docker 双实例 API/容器检查、合成上游 Pi Web 浏览器交互、桌面与手机截图。
- 状态：[TASK-20260927-013](2026-09-27-014-pi-web-sandbox.md)历史增量已验收；当时的沙箱依赖控制域模型连接，已被最新方向替代。`30207` 已升级为自主沙箱预览，`30208` 合成演示已退役。

## 4B. 自主配置的独立 Agent 沙箱（首轮完成）

- 目标：管理端只用名称快速创建独立 Pi Web 沙箱，模型和其他 Pi 能力由各自沙箱配置；保留启停、恢复与删除。
- 范围：解开新沙箱对模型代理任务/连接的数据库和服务依赖；独立目录、访问凭据、可出站网络、兼容旧数据、页面与 API。控制域模型代理和 QA 不在新沙箱调用路径。
- 可观察验收：无控制域连接也能创建两个沙箱；各自 Pi Web 内配置互不影响，停止恢复保留会话与配置，删除仅清理目标；合成上游调用不经过控制域代理。
- 验证方式：隔离 WSL Docker 项目中执行迁移、API、双实例 Pi Web/网络、生命周期和浏览器端到端；验收后移除临时容器与网络。
- 状态：[SBX-005](../questions/2026-09-27-005-autonomous-sandbox-egress.md) 已选择可信本地直接出站；[TASK-20260927-014](2026-09-27-015-autonomous-sandbox.md)实现、复审及合成验收完成。产品预览 `30207` 已升级并可创建新式沙箱；真实供应商需按目标网络单独验证。

## 4C. 沙箱容器探针与工作状态

- 目标：管理端可靠展示每个 Agent 的运行与就绪状态，逐步增加可核实的活动摘要。
- 范围：首轮读取 Docker 运行状态和 Pi Web 健康检查、采集时间与错误；后续事件适配器单独设计，不读取或展示模型凭据。
- 可观察验收：正常、停止、异常退出和探针失败分别显示准确状态及最后采集时间；没有事件时不声称 Agent 空闲。
- 验证方式：容器状态注入与管理页检查，验证两个沙箱不会串数据。
- 状态：首轮容器状态、Pi Web 就绪、采集时间及未知故障显示随 4B 实施并验收；细粒度 Agent 活动事件为后续候选。

- 验证方式：使用含多页、空白页及解析失败样例的端到端测试。

## 6. 提供可管理的 Agent 配置

- 目标：用户可选择系统提供的 Agent，并在权限范围内添加个性化 Skill 与资料。

## 7. 增加即时通讯通知和结果链接

- 目标：用户在任务状态变化时通过选定的即时通讯渠道得到通知并返回 Web 查看结果。
- 范围：单一待选平台的身份绑定、完成或失败通知与结果链接；首版不含双向对话。
- 可观察验收：已绑定用户能收到属于自己的任务通知，链接进入相应任务；未绑定或无权用户无法看到任务内容。
- 验证方式：使用测试账号验证发送、失败重试与访问权限。
- 状态：候选；依赖条目 4、身份方案及 IM 平台选择。

## 8. 持久操作幂等与生命周期可靠性扩展

- 目标：创建或操作响应丢失时能可靠识别同一操作，保留任务数增长后仍可检索与诊断。
- 范围：持久幂等键、无容器的到期授权元数据清理、任务分页和结构化操作审计；多人配额与多实例协调在适用需求确认后设计。
- 可观察验收：重复创建不会产生第二个环境；孤立授权可被识别且不误删受管任务；历史任务可分页访问，操作记录不含凭据或正文。
- 验证方式：丢失响应、服务重启和部分失败注入；数据库、归属与脱敏检查。
- 状态：新发现的候选；首轮单实例合成闭环可继续，真实多人或生产运行前重新评估优先级。风险见[运行评审](../reviews/2026-09-27-011-pi-task-runtime.md)。

## 9. 真实模型问答与上下文容量验证

- 目标：在管理员配置的供应商上核对已确认问答样例，并为长历史提供可诊断的容量边界。
- 范围：供应商协议/语义复验、上下文预算和错误分类、历史增长设计；如需检索或摘要及额外模型费用，先说明取舍并确认影响。
- 可观察验收：真实回答正确关联林晨/周宁/30天；无预算依据不编造；冲突资料不擅选版本；超预算明确反馈且不静默丢弃资料或历史。
- 验证方式：合成样例的真实供应商人工语义核验、预算边界与长历史端到端测试。
- 状态：新发现的候选；依赖已配置供应商及模型容量信息。资料实现已交付，不以固定上游推定本条完成。
