## 技术证据与结论

1. [CLI 参数解析](../../refer/pi-main-0.87.1/packages/coding-agent/src/cli/args.ts)支持 RPC、禁用工具、扩展、Skill、上下文文件及指定会话目录。`--no-extensions` 禁用发现，显式 `-e` 仍能加载扩展。运行服务应生成受控参数，白名单待设计。
2. [RPC 文档](../../refer/pi-main-0.87.1/packages/coding-agent/docs/rpc.md)规定 JSONL 通信，stdout 为协议、stderr 为诊断。`prompt` 成功不等于完成，`agent_end` 后可能继续；应处理 `agent_settled`、prompt disposition、取消、超时和进程退出。
3. [RPC 实现](../../refer/pi-main-0.87.1/packages/coding-agent/src/modes/rpc/rpc-mode.ts)的 `bash` 分支直接调用 `session.executeBash`，未以模型工具列表阻止执行。禁用模型 bash 工具不足以禁止宿主发起 shell 命令。后台需限制允许的 RPC 命令，不能直接透传浏览器请求。这是设计约束建议，尚未运行验证。
4. [安全文档](../../refer/pi-main-0.87.1/packages/coding-agent/docs/security.md)明确 cwd 与项目信任不是隔离边界。资料可能包含指令；挂载、权限、扩展来源、网络及凭据需要运行边界控制。
5. 本轮只读 Docker inspect 确认现有试用容器运行中，有两个命名卷、2 GiB 内存、2 CPU 和 256 PID 限制。本轮未修改试用环境；该检查不证明任务隔离或恢复通过。
6. 2026-09-27 使用同版本 Pi 试用镜像另起一次 `docker run --rm -i --entrypoint pi` 临时容器，传入 `--mode rpc --no-session --no-tools --no-extensions --no-skills --no-context-files`，stdin 发送 `{"id":"probe-1","type":"get_state"}`。进程退出码 0，stdout 返回对应 `get_state`、`success:true` 的 JSONL response；没有调用外部模型，返回的模型为 `unknown`。这验证 RPC 入口可启动及读取状态，不验证问答、事件流、会话恢复、命令权限或任务隔离。

## 停止与恢复的区别

停止再启动同一个容器通常保留可写层和卷，进程内存不保留。删除重建只保留明确持久化的数据；系统目录内安装的依赖不会因保存工作卷自动恢复。设计需区分保留停止容器与可重建环境快照，不能宣称卷方案已满足全部依赖恢复要求。

指定 `--session-dir` 不等于恢复正确会话，仍需验证显式会话恢复。Pi 空闲不自动等于 Workspace 任务结束；结束、继续与取消应在需求和状态设计中明确。
