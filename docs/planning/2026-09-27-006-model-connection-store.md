## 目标与边界

在独立 PostgreSQL 测试实例证明批准 origin、模型连接元数据和加密凭据能够持久化，且仅模型代理侧持主密钥才能解密。为后续管理接口和产品代理提供内部存储边界。

- 包含：版本化数据库迁移；批准 origin 与连接的内部写入/读取；AES-256-GCM 独立 nonce 与绑定连接身份及目标的认证数据；严格读取外部 32 字节主密钥文件；合成数据集成测试。
- 不包含：管理 HTTP API/Web、真实供应商凭据、产品代理服务、任务令牌、密钥备份和轮换、现有开发数据库迁移。测试连接采用合成公网 DNS 结果，不访问供应商。
- 依赖：已确认的 MOD-002、MPX-001 和 MPX-003；现有 Node 24、`pg`、出站目标策略及 WSL Docker。
- 可回退假设：首个内部格式使用单一密钥版本 1，密钥以原始 32 字节文件注入；后续轮换需专门迁移。测试只创建临时容器，不触碰 Compose 数据卷。

## 完成定义与验证

1. 迁移可重复执行；批准 origin 精确控制连接创建；保存后重连数据库可读取非敏感元数据，密文与 nonce 不等于明文且不通过元数据查询返回。
2. 正确主密钥可解密合成凭据；错误主密钥、篡改密文或绑定字段均返回稳定脱敏错误；缺失或错误长度的密钥文件被拒绝。
3. TypeScript 检查、聚焦集成测试及现有策略/传输回归在 WSL Docker 内通过；临时数据库和网络清理，现有 API、数据库和 Pi Web 试用容器不受影响。
4. 开发者验证、只读评审、验收与剩余风险记录完成。
