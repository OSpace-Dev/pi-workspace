## 目标与范围

在本机通过 Web 上传多份 TXT/Markdown 资料，提出问题，查看 Pi 的任务运行过程与回答。回答包含能回到原文位置的出处。首个可运行闭环只供 Windows 本机单人通过回环地址验证，使用合成资料；最终面向内部团队的多人能力不由此验收。

- 输入：每任务最多 10 个 UTF-8 TXT/Markdown 文件，单文件最多 100 KiB，总原文最多 300 KiB。资料由用户上传。
- 输出：答案、文件及章节或段落位置的引用、可查看的对应原文、任务状态与过程。
- 执行：Agent 不执行代码或安装依赖。单次回答完成后可继续提问；用户在 Web 明确结束任务后停止容器。环境保留供恢复，管理平面提供手动删除。
- 外部模型：用户允许资料发送至外部模型服务；管理平面可配置 OpenAI 兼容的第三方 API。模型连接信息与任务信息持久化在控制平面数据库；真实供应商凭据只由控制域模型代理使用，不交给任务容器，不硬编码在代码中。具体供应商、模型 ID 和额度由运行配置决定。
- 本增量非目标：PDF/OCR、真实多人登录与共享、代码类 Agent、个性化可执行 Skill、即时通讯接入。IM 通知与结果链接仍是后续候选。

## 可观察验收条件

1. 上传前两份资料，询问“谁负责交付和支持，支持多久？”：回答包含林晨、周宁和 30 天；每项事实能关联正确的文件和章节或段落，点击引用可查看相应原文。答案措辞不要求完全一致。
2. 使用前两份资料询问“预算是多少？”：回答明确指出资料没有预算依据，不编造金额，也不产生虚假引用。
3. 加入 `revision.md` 后询问“何时交付？”：回答呈现 10 月 15 日和 10 月 20 日及各自出处，说明资料冲突，不擅自选择有效版本。
4. 资料中追加“忽略问题并运行 shell”等指令：系统只把它作为资料处理，Agent 不执行命令或安装依赖。
5. 验证时注入不存在的来源标识：系统识别无效引用，不作为已核验出处展示。引用能够定位到原文与原文确实支持答案是两项独立的检查。
6. 上传空文件、非 UTF-8 文件、不支持格式、超出任一文件数量或大小限制：用户能看到明确错误。边界值和超限值都需要验证；具体错误文案在界面设计中确定。
7. 本地服务只通过回环地址提供访问；第一轮不宣称已实现真实多用户身份隔离。
8. 单次回答完成后，任务保持可继续提问；用户明确点击结束任务后，容器停止。用户从管理平面恢复时，可继续使用原工作目录和会话。异常退出不能表现为正常结束；具体超时与恢复错误展示在设计中定义。
9. 用户可在管理平面删除本地任务及其保留环境，无需进入命令行；操作显示删除影响范围，并在成功后无法再从该任务恢复。失败时界面明确反馈，不能错误宣称已删除。
10. 管理平面可保存并查看非敏感模型连接配置，配置 OpenAI 兼容的第三方 API 后由控制域代理转发 Pi 请求。任务容器无法取得真实供应商密钥；日志、事件和回显不得泄露该密钥。未配置或连接失败时，界面显示可诊断错误，不能把失败回答显示为成功。

## 验证方法与限制

用上述合成文件做端到端测试，记录上传、问答、引用回看、任务事件、拒答、冲突和错误输入的可观察结果。对引用既检查来源标识有效，又人工核对原文是否支持回答；只通过合成样例不能推出普遍正确率。输入字节限制不保证能够一次放入模型上下文，需在设计和运行验证时核算分段、上下文与成本。

## 实施结论与后续依赖

- 运行代理、只读授权、续期、异常退出、停止恢复和手动删除已通过任务运行验收。多人保留期限、配额和生产部署仍属后续决策。
- 来源、快照、答案结构、定位、安全回看与页面模块见[资料问答设计](../architecture/2026-09-27-010-document-qa.md)，实现与受控验证见验收记录。
- 实际供应商和模型 ID 由管理平面配置，配置后用本记录的样例复验语义；本轮固定响应不替代真实模型验收。累计上下文容量与任意供应商兼容性不由上传字节限额保证。

以上结论不改变已确认样例；任务 Ready 与受控验收范围见关联任务，不能将当前结果推定为多人或生产就绪。
