- 依据：[首个工作空间目标](../questions/2026-09-26-001-first-usable-scope.md)、[沙箱生命周期](../questions/2026-09-26-003-sandbox-isolation.md)、[本轮请求](../planning/2026-09-27-014-pi-web-sandbox.md)

## 目标

管理端提供显眼的“沙箱”入口，单人本地管理员选择模型连接、命名并启动新环境。每个环境运行独立 Pi Web，能从管理页打开，查看其自己的会话与文件；两个沙箱互不共享工作目录、Pi 数据和访问密码。管理页可观察运行状态，并可停止、恢复和删除，后者清理容器、授权与保留目录。

## 本地增量边界

- Pi Web 与资料问答任务是不同类型；资料问答继续使用无工具 bridge，既有任务与预览不迁移。
- Pi Web 的文件/工具能力只作用于新沙箱内的非 root 进程和独立工作目录。容器禁止提权、没有 Docker socket、无普通公网出口；不宣称抵御恶意多租户或内核漏洞。
- 模型请求通过已有代理和任务令牌，沙箱不持真实供应商密钥。选定连接必须已启用；无连接时不创建。Pi Web 自身的模型设置入口可能允许用户输入凭据，本地演示不使用该入口配置真实密钥；其容器没有普通公网出口。
- Pi Web 仅通过本机回环动态端口可达，并要求沙箱专属随机密码。管理端登录后可查看和复制密码。Docker 管理员能检查容器环境，不把此方案推定为远程生产鉴权。
- 沿用本地手动删除与停止/恢复规则。生产、多人权限、代码依赖安装及沙箱保留期限另行设计。

## 验收

1. 从管理导航进入 `/sandboxes`，创建带名称的沙箱，看到状态、独立 Web URL，点击后出现该沙箱 Pi Web 的登录页面；正确密码进入，错误或无密码拒绝。
2. 创建第二个沙箱，容器、工作目录、Pi 数据、密码和端口不同；它不能读取第一个沙箱目录。两个模型授权分别绑定连接。
3. Pi Web 可以创建会话并通过受控模型连接获取合成上游回答；沙箱不持上游真实密钥，非法目标不直连。
4. 停止后 Web 端口不再可用，代理授权撤销；恢复原容器、文件与会话，新授权生效；删除后 Web、容器、目录、数据库记录不可再访问。
5. 容器限制与现有 30141/30200～30206 身份保持有证据。错误、超时、网络/鉴权失败明确显示，不误报运行成功。

真实供应商语义、多用户、公开远程访问与任意代码的强隔离不由本轮验收证明。
