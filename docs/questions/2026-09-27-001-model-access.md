- 日期：2026-09-27
- 状态：MOD-001～002 已回复；具体供应商与密钥由管理平面配置，不在文档填写密钥
- 决策人：项目发起人
- 关联：[已确认需求](../requirements/2026-09-27-001-document-qa-local-slice.md)、[最小架构草案](../architecture/2026-09-27-001-local-workspace.md)

## 背景与证据

用户允许把首轮资料发送外部模型，首轮只使用合成资料且 Agent 无代码执行权限。Pi 0.87.1 支持多模型提供商，但具体服务、配额和凭据来源尚未确认。密钥一旦直接放进任务容器，会被容器内进程读取；使用模型代理可把真实密钥留在容器外，但需要额外服务和验证。当前无模型 RPC 握手成功，尚无真实模型问答证据。

### MOD-001：首轮使用哪类模型服务？

1. 已有外部模型账号（建议）：请只填写提供商和模型名称，不写密钥。复用现有配额，尽早验证 Pi 问答，但需要确认可用额度和接口。
2. 新申请外部模型账号：可单独管理费用，需要先完成开通。
3. 本地模型：资料无需外发，但需要确认 WSL 的算力、模型质量与上下文容量。
4. 其他，请说明。

回答区：1 可允许配置适配OpenAI的第三方API

结论（2026-09-27）：首轮允许在管理平面配置 OpenAI 兼容的第三方模型 API；不把单一供应商或模型名称写死。实际供应商、模型 ID 和兼容性需在运行配置及连接测试中确定。首个适配器优先验证 Pi 文档支持的 `openai-completions` 接口，其他兼容变体仍需逐一验证。

影响：Pi 配置、成本、上下文容量和运行验证。提供商与模型名称是选择项，不代表已验证适用。

### MOD-002：首轮如何向任务容器提供模型凭据？

1. 本地独立配置并在运行时交给任务容器（建议用于合成资料验证）：实现快；容器内进程可能读取凭据，任务事件与日志必须脱敏，后续代码 Agent 不可沿用此假设。配置不提交仓库，也不复用现有 Pi Web 试用容器的凭据卷。
2. 先实现模型代理：真实凭据留在控制域，任务容器通过限定代理访问；隔离更强，但增加首轮组件和网络策略工作。
3. 其他，请说明。

回答区：2 控制平面也是要数据库存储的吧，不能硬编码在代码啊，所以不存在仓库问题。

结论（2026-09-27）：首轮采用控制域模型代理，真实上游凭据不交给任务容器；模型连接和任务信息由控制平面数据库持久化，并通过管理界面维护，不硬编码在产品代码。数据库中的凭据应加密存储，解密主密钥不能与密文同存数据库，也不能提交仓库；任务容器只持有可撤销的代理访问令牌。具体加密、密钥注入和代理网络边界属于架构设计与验证。

影响：容器权限、网络和密钥管理。请不要在回答区填写密钥；具体安全输入方式须在技术设计中确定。

依据：[Pi 自定义兼容端点文档](../../refer/pi-main-0.87.1/packages/coding-agent/docs/models.md)。`models.json` 可指定 `baseUrl`、`api`、模型 ID 和供 Pi 识别的认证值；即便指向代理，配置及日志也不应包含真实上游密钥。
