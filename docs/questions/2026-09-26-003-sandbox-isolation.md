# Agent 沙箱的隔离边界

- 日期：2026-09-26
- 状态：首轮本地任务生命周期已确认；隔离和技术设计待确认
- 决策人：项目发起人
- 关联：[首个可用场景](2026-09-26-001-first-usable-scope.md)、[文档问答范围](2026-09-26-002-document-qa-scope.md)

## 背景与用户关切

用户希望快速启动服务器沙箱和 Pi Agent，并指出部分 Agent 会运行代码、安装依赖，因此质疑“一个 Pi Docker 容器”能否提供所需隔离。当前的 Pi Web Docker 是单人体验环境，不代表多用户 Workspace 架构。

## 已知证据

- Pi 0.87.1 的[安全文档](../../refer/pi-main-0.87.1/packages/coding-agent/docs/security.md)明确说明：生成的命令、扩展与子进程使用 Pi 进程的操作系统权限；项目信任不构成安全边界。
- Pi 的[容器化文档](../../refer/pi-main-0.87.1/packages/coding-agent/docs/containerization.md)支持完整 Pi 进程在 Docker 中运行，同时提醒挂载、环境变量中的凭据与网络访问仍会暴露给容器内代码。
- 首个增量已选择内部团队的多资料问答，Agent 不执行代码或安装依赖；代码类 Agent 放在后续增量。

## 暂定分析

一个长期共享的 Pi 容器会共享文件系统、进程权限、已安装依赖、会话和可能的凭据，无法形成用户或任务之间的隔离。一个独立容器可把 Pi、工具调用、用户代码和依赖安装约束在同一沙箱内，适合验证内部团队任务级隔离；容器本身仍共享宿主内核，隔离强度必须结合代码来源和威胁模型评估。

候选系统边界是：Web、身份权限、任务调度、审计、IM 接入等管理服务位于沙箱外；每次任务创建独立运行环境，Pi 与其工具、扩展和依赖安装都在环境内；只暴露必要资料、工作目录和受限模型访问；任务结束后停止并按策略保留环境。此为可行性方向，不是已确认架构。

对首个资料问答增量，默认禁用 shell、安装依赖与不需要的写文件工具，并用受控的资料读取接口提供内容。用户同时要求任务结束后可保留工作目录和已安装依赖；当前增量没有依赖安装行为，这一保留能力主要服务后续代码任务。若运行不可信第三方代码或对外多租户任务，需评估更强的微虚拟机隔离。

## 已确认边界

首个可运行增量不开放代码执行或依赖安装。用户明确结束任务后停止容器；需要时恢复原工作目录和依赖状态。首个增量尚无安装依赖行为，恢复依赖主要服务后续代码任务。本地合成资料验证由管理平面提供手动删除；多人平台的保留期限与配额仍待定义。

## 2026-09-27：首轮本地验证所需生命周期决策

背景：文档问答验收范围已在[需求记录](../requirements/2026-09-27-001-document-qa-local-slice.md)确认，结束后停止并可恢复也已确认。下面记录本地首轮可观察的结束和保留行为；多人平台的配额与保留期限可另定。决策人为项目发起人，回答原样保留。

### SBX-003：一次问答后何时停止容器？

1. 每次回答完成即停止（建议）：可立即验证停止/恢复；继续提问时启动同一环境并恢复会话，启动延迟会更明显。
2. 用户明确点击“结束任务”后停止：连续追问更快，但需要任务保持运行及空闲控制，首轮范围更大。
3. 其他，请说明。

回答区：2

结论（2026-09-27）：用户明确执行“结束任务”后才停止容器；单次回答完成后仍可在同一运行环境继续提问。空闲超时和异常退出的处理须在设计中明确，不能把单次回答完成等同于结束任务。

影响：任务状态、Web 操作、Pi 会话恢复、超时与容器资源占用。异常退出仍需独立记录错误状态，不视为正常完成。

### SBX-004：本地验证的保留与删除规则？

1. 本地手动删除（建议）：停止容器及资料、会话、结果持续保留，用户可主动删除；最容易验证恢复，但长期运行需另定配额、清理和备份策略。
2. 固定期限后自动删除：请注明天数；节省磁盘，但需要到期提醒与清理任务，过期后不能恢复。
3. 其他，请说明。

回答区：1 这个手动删除不能是进入命令行删除，而是在管理平面提供。

结论（2026-09-27）：本地合成资料任务持续保留，用户通过管理平面的删除操作移除环境及对应资料、会话和结果，不要求进入命令行。删除前需要明确影响范围，并在 UI 中反馈成功或失败；多人环境的配额和到期规则不由此决定。

影响：资料和凭据保留、磁盘使用、恢复、删除操作与数据风险。选择手动删除仅适用于本地合成资料验证，不自动成为多人平台的策略。
