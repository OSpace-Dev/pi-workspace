## 初评发现

- REV-20260927-007-F001，P1，`codes/src/model-proxy/task-grant-store.ts` 的中止轮换路径：轮换完成后，迟到的文件写入失败回调仍可中止新授权，导致已生效任务突然失去模型访问。修复方向是将轮换完成状态持久化并禁止完成后中止。初评时回流实现，未直接在评审阶段改代码。
- REV-20260927-007-F002，P2，`codes/src/model-proxy/task-grant-store.ts` 的再次轮换路径：若前任授权在待完成轮换期间到期，数据库仅剩新授权有效，旧条件会允许新授权再次轮换，产生未收口的连续轮换。修复方向是检查新授权的完成标记，不凭有效行数判断轮换已经完成。

## 复审结论

F001 已解决：新授权持久化 `rotation_completed_at`，完成和中止都在同任务事务锁下检查；完成操作可重复，中止已完成轮换返回稳定 `GRANT_NOT_ACTIVE`。回归测试显式调用“完成两次后迟到中止”，验证新令牌仍有效。F002 已解决：待完成的新授权即使其前任到期，也返回 `ROTATION_PENDING`；完成轮换后才可签发下一代。复查摘要存储、任务/连接绑定、有限到期、并发签发和禁用连接路径，未发现 P0～P2 剩余问题。

边界：此模块信任控制域调用者提供任务 ID 和有限到期时间；尚无任务主表或状态查询，不能单独宣称停止/删除后全系统立即失效。代理调用接入时必须检查任务状态并取消活动流。验收证据见隔离测试。
