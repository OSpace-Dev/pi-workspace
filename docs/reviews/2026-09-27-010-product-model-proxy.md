## 发现

- REV-20260927-010-F001（P2）：`codes/src/model-proxy/pi-request.ts` 允许省略 `max_completion_tokens`，导致上游自行选择输出上限，与设计的 4096 上限不一致。需补默认值并测试。
- REV-20260927-010-F002（P2）：`codes/src/model-proxy/active-streams.ts` 没有并发限制，授权令牌可以同时打开任意数量上游连接。首轮应保守限定单任务一条流与进程总上限，并验证取消后释放。
- REV-20260927-010-F003（P2）：Pi 集成探针未禁用 Agent 自动重试，断流产生 4 个增量，说明同一问题可再次请求；受控配置应关闭两层自动重试并核对上游调用次数。
- REV-20260927-010-F004（P2，开发浏览器验证发现）：客户端在无正文的 logout POST 中仍设置 JSON 内容类型，Fastify 拒绝并产生未处理异常。应只在提供 JSON 正文时设置内容类型，并覆盖退出流程。
- REV-20260927-010-F005（P2，收尾复核）：连接停用/更换凭据提交后，再查询数据库找到活动任务以取消流；若第二次查询失败，已提交的变更无法再次执行，活动流也未取消。活动登记应保存连接 ID，提交后直接取消关联流。

## 剩余风险

当前单实例进程内取消不是多实例机制。正式运行代理、只读令牌文件、自动轮换和恢复/删除仍未实现。合成 TLS 上游验证通过不代表任意供应商兼容。没有 Git 元数据，使用完整文件与调用链复核，无法检查 Git 差异。

## 复审

- F001：已解决。代理补 4096 默认值，纯函数测试覆盖省略值。
- F002：已解决。单任务一条、单进程八条；活动流的重复调用在集成测试中返回 429，停止后释放登记。
- F003：已解决。Pi 探针关闭两层重试，并以合成 TLS 上游逐场景计数断言每个场景恰好一次请求。
- F004：已解决。只有提供正文时设置 JSON 头；桌面与移动浏览器退出均完成，无页面异常。
- F005：已解决。登记项保存连接 ID；管理路由提交后直接取消本进程关联流，不再读取数据库。集成测试验证连接停用中断已有流、旧令牌的新调用被拒绝；并发保护测试验证其它连接不会被取消。
