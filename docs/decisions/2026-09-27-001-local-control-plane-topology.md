## 结论

控制平面采用 TypeScript/Node API、独立模型代理、独立 Docker 运行代理及 PostgreSQL 容器，全部在现有 WSL Docker 中开发运行。Web 框架在界面设计时选定。模型连接和任务状态存数据库；真实供应商凭据由模型代理持有，不进入任务容器。运行代理是唯一持有 Docker socket 的应用容器，Web、API、模型代理及任务容器无此挂载。

## 取舍与边界

分离模型凭据和 Docker Engine 权限增加服务数量，但使管理 API 不同时持有两种高风险能力。Docker socket 仍可能授予运行代理宿主级控制权；限定代理接口与资源归属只减少误用面，不改变该事实。首轮服务在本机回环入口验证，数据库和代理不发布宿主端口。此决策不等于生产部署、多用户隔离或不可信代码执行方案。

当前选择允许按价值顺序交付：先验证 API 与数据库容器化开发入口，再完成代理协议与任务容器生命周期。未实现的服务不预建空目录或空容器。若后续引入真实多人、代码执行或远程部署，重新评估运行代理权限、网络和密钥管理。
