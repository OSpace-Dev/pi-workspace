## 结论

1. 管理平面维护获准的 HTTPS origin 清单。模型连接只能指向清单中的目标；任务容器不得提供或覆盖目标。代理拒绝重定向、非 HTTPS、回环、私网、链路本地和其他非公网地址，检查 DNS 解析结果及实际连接地址。新增供应商由管理员增加清单项。
2. 控制平面为每项任务签发随机不透明代理令牌，数据库只存摘要，授权绑定任务与模型连接。任务停止、删除或更换模型连接时撤销；恢复时签发新令牌。运行中令牌有有效期，由控制域续期。

## 后果与实施边界

出站策略须从结构化 URL 取得规范化 origin，连接时重新解析并固定到已校验的地址，同时使用原域名验证 TLS 证书。只校验 URL 文本或先校验 DNS 后由 HTTP 客户端再次解析，都不足以兑现本决策。首个实现任务先验证这一出站策略；管理清单持久化及真实供应商调用随后实施。

令牌生命周期须与任务状态事务及容器恢复流程对齐，不能只靠容器停止阻止模型调用。有效期具体数值、续期触发和时钟偏差是后续详细设计项，不在本决策中猜定。真实供应商密钥仍由控制域代理使用并加密入库；本决策不授权明文密钥进入任务容器。参考[模型代理设计](../architecture/2026-09-27-002-model-proxy.md)。

当引入远程部署、多用户或代码执行 Agent 时，重新评估管理员权限、网络出站控制、DNS/代理链路、审计及令牌续期机制。
